## Data Classification: Internal Tier

ZFP Advisor handles **Internal** tier data only. This means:

- **Permitted**: Aggregate workforce metrics (hours, utilization %, headcount by department)
- **Permitted**: Project-level totals and business unit comparisons
- **Permitted**: Sending aggregate Power BI results to the Claude API for narration
- **NOT permitted**: Individual employee names, salaries, or personal data sent to Claude
- **NOT permitted**: Raw HR records with individual PII in any log file

## What data flows to Claude

1. The user's natural language question (typed by a ZFP leadership user)
2. The DAX query generated by Claude (no PII — pure query logic)
3. Power BI result rows (aggregate data only — business unit totals, project sums, etc.)

## What never leaves the Azure environment

- Azure AD credentials (POWERBI_CLIENT_ID, POWERBI_CLIENT_SECRET)
- Microsoft Bot Framework credentials (MicrosoftAppId, MicrosoftAppPassword)
- Anthropic API key (backend only; never exposed to frontend)
- Raw employee-level Power BI rows containing individual data

## Access control

- Azure App Service: HTTPS only, Azure AD service principal authentication
- Teams bot: Bot Framework JWT validation on every `/api/messages` request
- Frontend: No API keys, calls `/ask` endpoint only

## Logging policy

- Query hash (not raw DAX) is logged in `logs/queries.log`
- Row count is logged; row content is NOT logged in production
- No employee names, IDs, or salaries appear in logs
- Application errors logged to `logs/errors.log` with context only

## Incident response

If a data classification breach is suspected (e.g. employee PII sent to Claude):
1. Rotate `ANTHROPIC_API_KEY` immediately in Azure Key Vault
2. Rotate `POWERBI_CLIENT_SECRET` in Azure AD
3. Notify Abdalla Idris (CTO) and the ZFP IT Security team
4. Review `logs/queries.log` for the affected time window
